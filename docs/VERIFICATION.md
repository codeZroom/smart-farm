## 브라우저 → API → Supabase 검증 내용

1. 미로그인 보호 경로가 로그인으로 이동하고 잘못된 비밀번호 요청이 401을 반환했습니다.
2. 실제 로컬 Auth 이메일 계정으로 로그인했으며 HttpOnly 세션 쿠키를 확인했습니다.
3. 화면에서 농장/구역/장치를 생성하고 원문 키를 한 번 표시했습니다.
4. 별도 Node 시뮬레이터 프로세스가 동일한 수집 API에 정상 데이터를 전송해 201을 받았고 실제 Supabase 테이블에 행이 저장됐습니다.
5. 화면의 최신값·그래프·기간별 집계와 1시간/24시간/7일/30일 조회를 확인했습니다. 기간 선택 기능은 실제 저장된 짧은 구간 데이터로 검증했으며, 30일 분량 부하 테스트를 수행한 것은 아닙니다.
6. 고온/저온/고습/저습/센서 실패 시나리오에서 대응 알림을 확인했습니다. 테스트 대기 시간을 줄이기 위해 **로컬 DB에서만** 마지막 통신 시각을 과거로 조정했습니다. 실제 30초 장기 운전 내구성 검사는 별도입니다.
7. 401/413/422/429, CSRF Origin 거부, 키 회전 후 이전 키 거부, 비활성 장치의 새 키 거부를 확인했습니다.
8. 실제 두 번째 Auth 계정이 첫 사용자 농장·구역·장치·측정·임계값·알림을 볼 수 없으며 다른 사용자 구역에 장치를 등록하거나 키 해시를 읽을 수 없음을 확인했습니다.
9. 임계값 저장, 장치 이름 수정, 오프라인 검사 API와 알림 확인 처리를 실행했습니다.
10. manifest, 아이콘, 일반 프로필의 설치 조건, SW 오프라인 안내와 복구, 로그아웃 후 보호 경로를 확인했습니다. 자동화 기본 시크릿 컨텍스트의 `in-incognito` 제한은 일반 프로필에서 별도로 검증했습니다.

## 발견 후 수정한 문제

- Recharts/Redux와 Next/Sharp 타입 호환성: 호환 버전 고정 후 타입/빌드 통과.
- 시뮬레이터 top-level await의 CJS 실행 오류: 독립 async 진입점으로 수정 후 실제 전송 확인.
- 오프라인에서 오래된 HTML이 HTTP 캐시에서 반환되는 문제: SW navigation을 no-store로 변경하고 오프라인 안내 검증.
- 위험 상태가 정상 색상으로 표시되는 문제와 모바일 장치 라벨 줄바꿈: 상태별 배지/레이아웃 수정 후 화면 확인.
- 조회 대상이 없는 수정 요청의 거짓 성공: 단일 반환 행 확인으로 변경.
- npm audit에서 발견한 Zod/PostCSS 취약점: 수정 릴리스와 root override 적용 후 배포 의존성 감사 0건. npm 10.9.4로 lockfile 생성 및 의존성 트리 확인. npm 11.2의 override 트리 표시 오류를 피하려면 README의 고정 npm 설치 명령을 사용하세요.

## 미실행 / 외부 설정 필요

- 실제 iPhone Safari / Android Chrome 홈 화면 설치와 standalone 실행 (절차: PWA_SETUP.md)
- 실제 ESP32 업로드, SHT31 실측, Wi-Fi 단절 복구, NTP/TLS/HTTPS 전송
- 실제 배포 호스트에 맞는 루트 CA 인증서 설정
- Vercel 배포, 원격 Supabase migration/계정/SMTP/로그인 정책 설정
- 외부 오프라인 스케줄러 등록과 배포 상태에서 반복 실행
- 장기 운전, 수백 장치 이상 동시 부하, 데이터 보존/복구 훈련
- 비밀번호 변경 UI는 구현했으나 전체 브라우저 시나리오에서 실제 비밀번호 교체는 실행하지 않았습니다.

운영 DB와 운영 서비스는 변경하지 않았습니다. 최근 알림은 100건이며 대규모 장치 목록과 전체 알림 검색/페이지네이션은 후속 확장 항목입니다. 스케줄러 없이도 오프라인 표시는 계산되지만, 오프라인 알림 이력 생성은 스케줄러가 필요합니다.
